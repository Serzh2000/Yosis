# Linux сервер Yosis

Интерфейс и тулчейн работают на сервере. Web Serial/WebUSB обращаются к USB компьютера ученика из HTTPS браузера. Серверу не нужен доступ к USB учеников.

## Запуск

Для сервера нужны Docker Compose, DNS имя и HTTPS reverse proxy. Настройте переменные окружения перед запуском:

```sh
export YOSIS_PUBLIC_ORIGIN='https://fpga.school.example'
# Сгенерируйте отдельный случайный ключ каждому пользователю, минимум 32 символа.
export YOSIS_USERS_JSON='{"teacher":"<personal-random-key>","student1":"<another-personal-random-key>"}'
docker compose -f deploy/compose.yml up --build -d
```

Пример ключа можно создать на сервере командой `openssl rand -hex 32`. Секреты хранятся у администратора, не в Git, не в браузерном localStorage и не в публичных файлах сайта. Пользователь вводит свой ключ один раз на сессию; API выдаёт HttpOnly Secure SameSite cookie на восемь часов. Учётные записи здесь задаёт администратор. Регистрация, восстановление пароля и внешние OAuth провайдеры пока не реализованы.

Порт контейнера опубликован только на `127.0.0.1:3001`. Reverse proxy передаёт исходный HTTP Host; он должен совпадать с `YOSIS_PUBLIC_ORIGIN`. Пример Caddy находится в [Caddyfile](Caddyfile). Задайте `YOSIS_DOMAIN=fpga.school.example`, установите этот Caddyfile и запустите Caddy по инструкции вашего сервера. Proxy работает на том же сервере, что Compose. HTTPS завершается на proxy, backend принимает только разрешённый Host и Origin. Произвольный доверенный `X-Forwarded-Host` не используется.

Лимит попыток входа (10 неверных ключей в минуту) считается по адресу клиента. За reverse proxy все клиенты приходят с одного адреса сокета, поэтому без дополнительной настройки десять неверных попыток любого человека блокировали бы вход всем. `YOSIS_TRUSTED_PROXY_HOPS=1` (задан в `compose.yml`) включает чтение адреса клиента из `X-Forwarded-For`: берётся запись, добавленная ближайшим доверенным proxy (отсчёт справа), левые записи игнорируются. [Caddyfile](Caddyfile) перезаписывает заголовок адресом соединения. Включайте переменную только если трафик действительно проходит через такой proxy и порт контейнера недоступен напрямую; иначе клиент сможет подставить любой адрес и обойти лимит. Если перед Caddy стоит ещё один proxy или CDN, адрес клиента нужно настроить отдельно: уберите перезапись `header_up`, задайте в Caddy `trusted_proxies` и укажите в переменной общее число proxy.

Без `YOSIS_PUBLIC_ORIGIN` API остаётся в локальном режиме: только loopback Host, тот же Origin и известный Vite Origin в разработке. Для listen на внешнем адресе требуются public Origin и персональные ключи; при отсутствии ключей запуск завершается ошибкой.

## Версии и сборка

Dockerfile использует официальные Node 22.23.3 и Python 3.13.9 по digest, подписанный Debian snapshot 2026-10-01 и Icarus `11.0-1.1+b1`. YoWASP Yosys фиксируется package-lock.json. Nextpnr, Apicula и все восемь зависимостей Python фиксируются версией и SHA-256 опубликованных колёс в [gowin-requirements.txt](gowin-requirements.txt). `pip --require-hashes --only-binary=:all:` отклоняет подмену или незакреплённую зависимость.

Сервер собирается в `.server-dist/index.mjs`; production запускает Node, без tsx. Linux инструменты находятся в `/usr/bin` и `/opt/gowin`; путь запуска не зависит от текущего рабочего каталога.

Версии и digest проверены по [реестру официальных образов Node](https://github.com/docker-library/official-images/blob/master/library/node), Docker Registry и [пакету Icarus Debian](https://packages.debian.org/bookworm/iverilog). На текущей Windows машине Docker отсутствует, поэтому сборка и запуск контейнера здесь ещё не выполнены. Это рецепт развёртывания с закреплёнными зависимостями; подтверждение полного Linux цикла остаётся обязательной проверкой на целевом сервере.

## Данные и ограничения

Именованные тома `data` и `cache` переживают пересоздание контейнера. В `/data` находятся приватные задания, библиотека проектов, прогресс и резервные копии отладчика. Этот каталог никогда не раздаётся как статические файлы. Резервные копии администратора должны включать весь том `data`.

Каждая сборка, симуляция и размещение получает владельца. Чужие status, detail, artifact, cancel и использование чужого синтеза для размещения возвращают 404. Владение сохраняется на диске после перезапуска. API библиотеки и курса разделяет пользователей по отдельным каталогам. Библиотека допускает до 50 проектов и 100 МиБ на пользователя; изменение существующего проекта требует актуальной revision и отвергает потерю параллельных изменений кодом 409. Прогресс ограничен 64 КиБ. Резервные копии отладчика неизменяемы, проверяются SHA-256 и ограничены 64 МиБ на пользователя.

У пользователя может быть до четырёх активных или ожидающих заданий и до 30 запусков за час. Отдельные очереди по умолчанию имеют одного исполнителя; количество исполнителей настраивается от 1 до 8. Проверка синтаксиса имеет отдельную ограниченную очередь, 20 секунд на запрос и одну актуальную проверку на пользователя: новый запрос отменяет старый.

Ротация хранит до 64 завершённых запусков в каждом каталоге, максимум семь дней и 512 МиБ. Она проверяет UUID, метаданные, маркер созданного задания и исключает активные задания, посторонние каталоги, fixtures и ссылки. Для старых каталогов `.builds`, `.simulations`, `.physical` распознаются корректные метаданные, созданные прежней версией. Исходные проекты и резервные копии этой ротацией не затрагиваются. Очистка запускается при старте и после завершения задания. Лимит диска относится к сохранённым завершённым заданиям; одновременно выполняющиеся задания временно добавляются к объёму.

Compose ограничивает весь контейнер шестью ГиБ RAM, двумя CPU и 128 процессами, снимает capabilities, включает read-only root и `no-new-privileges`. Дочерние Node процессы ограничивают JS heap; native Linux процессы наследуют CPU deadline и лимит файла 64 МиБ через `prlimit`, Icarus также ограничен одним ГиБ адресного пространства. Отмена Icarus/nextpnr завершает всю Linux группу процессов. Wasmtime резервирует большой виртуальный диапазон, поэтому ограничение адресного пространства на него не накладывается. Индивидуальные cgroups на каждый worker, отдельные контейнеры пользователей и проверки публичного сервера под нагрузкой пока не реализованы. Общий контейнер и квоты дают рабочую основу для контролируемого школьного сервера; полноценную изоляцию враждебных tenants они не доказывают.

## Переменные окружения

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `YOSIS_API_PORT` | API порт, `3001`; общая `PORT` игнорируется |
| `YOSIS_LISTEN_HOST` | Адрес listen, `127.0.0.1` |
| `YOSIS_PUBLIC_ORIGIN` | Единственный HTTPS Origin публичного интерфейса |
| `YOSIS_USERS_JSON` | JSON объект имя → персональный случайный ключ |
| `YOSIS_WORKSPACE` | Корень приложения; иначе определяется от серверного модуля |
| `YOSIS_DATA_DIR` | Приватное хранилище; по умолчанию корень приложения |
| `YOSIS_BUILD_CONCURRENCY` | Исполнители синтеза, `1` |
| `YOSIS_SIMULATION_CONCURRENCY` | Исполнители симуляции, `1` |
| `YOSIS_PHYSICAL_CONCURRENCY` | Исполнители размещения, `1` |
| `YOSIS_JOB_RETAIN_COUNT` | Завершённые задания на каталог, `64` |
| `YOSIS_JOB_RETAIN_DAYS` | Возраст завершённых заданий, `7` |
| `YOSIS_JOB_RETAIN_MB` | Объём завершённых заданий на каталог, `512` МиБ |
| `YOSIS_MAX_USER_JOBS` | Одновременно активных заданий на пользователя (публичный режим), `4` |
| `YOSIS_MAX_JOBS_PER_HOUR` | Запусков заданий на пользователя в час (публичный режим), `30` |
| `YOSIS_TRUSTED_PROXY_HOPS` | Число доверенных reverse proxy перед сервером. Без значения X-Forwarded-For игнорируется. Сейчас используется для лимита попыток входа |
| `YOSIS_NEXTPNR`, `YOSIS_GOWIN_PACK` | Явные пути инструментов |
| `IVERILOG_PATH`, `VVP_PATH`, `IVERILOG_LIB` | Явные пути Icarus |
| `YOWASP_CACHE_DIR`, `XDG_CACHE_HOME` | Записываемый кэш WASM инструментов |

Лимиты заданий действуют только в публичном режиме. Некорректные значения (не положительное целое) останавливают запуск сервера. В локальном режиме (без `YOSIS_PUBLIC_ORIGIN`) часовой квоты нет, а число одновременных заданий ограничено сверху (16) только как защита от зацикленного клиента.

Очистка завершённых заданий (`YOSIS_JOB_RETAIN_*`) остаётся общей для каталога, но справедлива к пользователям: возраст применяется ко всем одинаково, а при превышении общего числа или объёма место освобождает владелец (`.owner.json`) с наибольшим числом заданий либо объёмом, начиная с его самых старых. Готовая сборка тихого пользователя не удаляется из-за чужих запусков. Задания без владельца (локальный режим, старые каталоги) считаются одним владельцем.

## API для клиента

`GET /api/session` возвращает `{user, local}` либо 401. `POST /api/session` принимает `{token}` и устанавливает cookie; `DELETE /api/session` завершает сессию. Для CLI допустим `Authorization: Bearer <personal-key>`.

`GET /api/projects` возвращает краткую библиотеку. `GET /api/projects/:id` возвращает `{project, revision, updatedAt}`. `PUT /api/projects/:id` принимает `{project}` и `If-Match: <revision>` для изменения существующего проекта. `DELETE` удаляет конкретный проект. `GET/PUT /api/progress` читает или сохраняет объект состояния курса.

`GET /api/builds/:id/status?logOffset=N` и аналогичные `/api/simulations`, `/api/physical` возвращают статус и только новые символы журнала, `nextLogOffset` и `logReset`. Нетлисты, VCD и placement в этот ответ не входят. При terminal статусе клиент один раз запрашивает полный `GET /:id`. Смещение считается в символах JavaScript строки, не байтах UTF-8.

`POST /api/syntax` принимает `{project}` и возвращает `{diagnostics, error?}` после чтения Verilog, проверки hierarchy и RTL. Gowin отображение и размещение не запускаются. Закрытие HTTP запроса отменяет проверку.
