# DirtyJTAG для Tang Nano 20K

> Обновление 4 октября 2026: опубликован **dirtyjtag-v2-yosis-winusb-3**. Замечания к C-границам/владению USB и применению настроек UART исправлены в overrides и пересобранном образе. Native harness исполняет настоящий C-обработчик: 14 групп и 20 000 пакетов с UBSan. Добавлены повторный выбор ROM-порта, reset при disconnect и защищённые серверные копии с проверкой до записи. Старые разделы находок ниже описывают причину изменений. Полная аппаратная приёмка новой версии остаётся открытой; `winusb-3` на плате не запускалась (на ней установлена `winusb-2`).

3 октября 2026. Браузерный установщик и комплект прошивки реализованы. На одной плате сборка `winusb-2` установлена браузерным установщиком и получила драйвер WinUSB автоматически; JTAG, UART и восстановление заводского образа записью не проверены (см. ниже).

Полное ревью выявило ошибки границ буферов в C-обработчике DirtyJTAG и неработающее изменение скорости UART. Они исправлены в текущем бинарнике (`winusb-3`); аппаратно эта сборка не проверялась. Комплект пока предназначен для разработки и испытаний. [Ревью, процедура и критерии приёмки](../../docs/dirtyjtag-install-review.md).

Образы и манифест находятся в `public/firmware/dirtyjtag`. Установщик проверяет размер и SHA-256 перед записью и принимает только встроенный комплект.

Основа: [DirtyJTAG `64fe564b`](https://github.com/pepijndevos/bl616_dirtyjtag/tree/64fe564b82e509e9aa0ff3372a95ca5e2edf9230), [Bouffalo SDK v2.3.16](https://github.com/bouffalolab/bouffalo_sdk/tree/6ebf1d053287e0417bb37e2322dfda9665febf86), GCC T-Head `072fc29d`. Адрес `0x20000` взят из закреплённого `flash_prog_cfg.ini`; старый README upstream упоминает прежний `0x40000`.

## USB

- JTAG: VID/PID `1209:c0ca`, vendor interface 0, пакеты 64 байта, Full Speed.
- BOS и MS OS 2.0 объявляют `WINUSB` только для interface 0. CDC-интерфейсы 1/2 сохраняются для UART.
- USB serial формируется из прочитанного идентификатора BL616. eFuse не записываются.
- `bcdUSB=0x0201`, `bcdDevice=0x0203`, GUID `{11F92E43-591F-4F45-9057-47F4B31830A2}`.

Дескрипторы проверены в настоящем двоичном образе. Для `winusb-2` (индекс конфигурации 0, `bcdDevice 0x0202`) на одной плате Windows перечислила `MI_00` со службой `WINUSB` и `MI_01` (COM14) со службой `usbser` без ручной установки драйверов. Для `winusb-3` перечисление, а также обмен по UART и JTAG надо подтвердить.

## Установка и восстановление

Вкладка «Подключение» → «Отладчик». Удерживая UPDATE за HDMI, пользователь подключает USB и выбирает Bouffalo CDC. Web Serial обращается к штатному ROM.

Подготовка читает BootInfo, параметры flash и весь её объём. Содержимое проверяется командой raw-flash SHA-256 и сохраняется в IndexedDB. Транзакция использует строгую долговечность; копия перечитывается и проверяется. До успешного сохранения стирание недоступно.

Перед записью проверяются та же плата, JEDEC, ёмкость и отсутствие изменений flash после подготовки. Текущий пакет допускает наблюдённый ROM `0x06160001`, `sign=0`, `encrypt=1`; другие профили требуют отдельной проверки. Вторичная прошивка записывается первой, тело загрузчика — следом, сектор 0 с заголовком — последним. Запись не атомарна. Кадр записи занимает один USB-пакет (8 байт заголовка + 32 байта данных, `WRITE_CHUNK = 32`): на плате кадры из нескольких пакетов (2056 и 264 байта) приводили к остановке ответов ROM, причина не установлена. Изменяются только необходимые секторы; промежутки и остатки секторов сохраняются. Проверяется SHA-256 каждого сектора и всей flash.

При обрыве нужно вернуться в BOOT и выбрать восстановление. Самая ранняя копия конкретного BL616 сохраняется отдельно от последующих. Неудачная запись автоматически не повторяется. Очистка данных сайта или смена профиля браузера лишает доступа к копии; проверенная копия дополнительно хранится на сервере участника.

В протоколе нет команд eFuse, полного стирания чипа, произвольной памяти и исполнения образа. Flash FPGA с пользовательской программой этим мастером не записывается.

## Сборка разработчиком

Готовые образы раздаются статическими файлами, в том числе с Linux-сервера. На компьютере ученика инструменты не требуются. Повторная сборка прошивки сейчас поддерживает Windows-разработчика с Python:

```powershell
python scripts/prepare-dirtyjtag-deps.py
python -m pip install --target .tools/dirtyjtag-build/python cmake==3.31.6 ninja==1.11.1.4
python scripts/build-dirtyjtag.py
```

Подготовка получает закреплённые деревья Git и проверяет Git blob hash каждого файла. Сборка не открывает USB. Исходники upstream сохраняются в `upstream/`; USB-добавления — в `yosis_usb.inc`, исправления C — в `overrides/`. Лицензии включаются в комплект статических файлов.

## Проверка

14 тестов `tests/bl616-flash.test.ts`: настоящий комплект, независимый ROM/NOR, фрагментированные ответы, установка и восстановление, прерванная запись, подмена платы/flash/пакета, повреждённая или удалённая IndexedDB-копия, отдельный бюджет SHA, порядок boot header и освобождение порта. Общая регрессия после ревью: 301/301; TypeScript и Vite build прошли. Эти проверки не исполняют MCU firmware и не заменяют аппаратную приёмку.
