# Verilog в Moodle: автопроверка через VPL и Icarus Verilog

На `cdod.sakoryagin.ru` стоит плагин **VPL (Virtual Programming Lab) 5.0.1**. Код учеников
выполняет отдельный сервис `vpl-jail-system` (песочница) на том же сервере; Icarus Verilog 12
в песочнице доступен.

## Как устроено на сервере

| Что | Где |
| --- | --- |
| Плагин | `/var/www/fastuser/data/www/cdod.sakoryagin.ru/public/mod/vpl` |
| Песочница | сервис `vpl-jail-system` (`systemctl status vpl-jail-system`), конфиг `/etc/vpl/vpl-jail-system.conf`, журнал `/var/log/vpl/vpl-jail-system.log` |
| Адрес песочницы | сама слушает только `127.0.0.1:8180`; наружу открыта через nginx сайта по `https://cdod.sakoryagin.ru/<секрет>` (см. `nginx-vpl.conf`); секрет лежит в `/root/vpl/urlpath.txt` и записан в настройке Moodle `mod_vpl/jail_servers` |
| Лимиты | 120 с, 512 МБ, 100 процессов на запуск |
| Бэкапы базы | `/root/moodle-db-before-vpl-20261113.sql.gz`, `/root/moodle-db-before-course-20261113.sql.gz` |

Песочница строит `/jail` из файлов сервера, поэтому после запуска сервиса несколько минут идёт
сканирование диска и порт 8180 открывается не сразу.

## Курс «Verilog: первые шаги» (скрыт)

Создан скриптом `create_course.php` из папки `tasks/`: курс `VerilogStart` (скрытый, id 7) и
пять заданий для нулевого уровня:

1. Провод (`assign y = a;`)
2. Инвертор (`~`)
3. И и ИЛИ (`&`, `|`)
4. Полусумматор (`^`, `&`)
5. Мультиплексор 2 в 1 (`? :`)

У каждого: описание с таблицей истинности, заготовка с пропуском, тестбенч перебирает все
входы. Каждое следующее задание открывается, когда за предыдущее набрано не меньше 60 из 100.
Максимальная оценка каждого задания 100.

Чтобы открыть курс ученикам: Moodle → курс → «Настройки» → «Видимость курса: показать»,
затем запишите учеников на курс.

Повторный запуск создаёт только недостающие задания:

```sh
sudo -u fastuser php -d max_input_vars=5000 create_course.php \
  /var/www/fastuser/data/www/cdod.sakoryagin.ru /путь/к/tasks "Verilog: первые шаги" VerilogStart
```

(`create_course.php` ищет `vpl_evaluate.sh` и `vpl_run.sh` рядом с папкой `tasks/`. Папка должна
быть читаема пользователем `fastuser`, не лежать в `/root`.)

## Как сделать своё задание

Скопируйте папку из `tasks/` и поменяйте файлы:

| Файл | Что это |
| --- | --- |
| `title.txt` | название задания |
| `file.txt` | имя файла ученика, например `half_adder.v` |
| `description.html` | условие для ученика |
| `starter.v` | заготовка, которую ученик видит в редакторе |
| `tb.v` | тестбенч преподавателя (ученик его не видит) |
| `solution.v` | эталонное решение (только для проверки; в Moodle не попадает) |

Тестбенч печатает по строке на проверку, оценка = доля проверок `PASS`:

```
CHECK PASS a=1 b=0
CHECK FAIL при a=1 b=1 ожидалось y=0, получено y=1
```

Тестбенч должен заканчиваться `$finish`, иначе симуляция остановится по таймауту 10 с.

## Как работает оценка

`vpl_evaluate.sh` компилирует `tb.v` и все остальные `.v` (`iverilog -g2012`), запускает `vvp`,
считает строки `CHECK`. Оценка = `VPL_GRADEMAX × PASS / (PASS + FAIL)`, то есть в шкале задания.
Ошибка компиляции, таймаут и запрещённые задачи (`$system`, `$fopen`, `$readmem`, `$dumpfile` и т. п.)
дают 0 с пояснением; к типовым ошибкам компилятора добавляются подсказки по-русски.

Проверяется поведение схемы в симуляции, а не синтезируемость.

## Как открывается задание

Ссылка на задание в курсе открывает сразу редактор кода: условие и поле для кода на одной странице
(кнопки «Запуск» и «Оценить» в панели редактора). Описание и настройки (файлы исполнения, оценка)
открываются вкладкой «Описание» или адресом `view.php?id=...&info=1`.

Редактор открывается на весь экран, без вкладок Moodle; выйти можно кнопкой «Обычный экран» в панели
редактора, а адрес `forms/edit.php?id=...&full=0` открывает его без полного экрана.

Это делает небольшая правка плагина `patch_vpl_open_editor.py` (три файла, оригиналы сохраняются как
`*.orig`). После обновления плагина VPL её нужно применить снова:

```sh
python3 patch_vpl_open_editor.py /var/www/fastuser/data/www/cdod.sakoryagin.ru/public/mod/vpl
```

## Почему песочница открыта через nginx

При «Оценить» и «Запуск» страница в браузере ученика подключается к песочнице по WebSocket. Если в
`mod_vpl/jail_servers` указать `127.0.0.1`, браузер полезет на компьютер ученика и спросит про доступ к
локальной сети. Поэтому адрес публичный (`https://cdod.sakoryagin.ru/<секрет>`), а nginx передаёт
запросы на `127.0.0.1:8180`. Конфигурация: `nginx-vpl.conf`. Заголовок `Server` песочницы нужно
пропускать как есть (`proxy_pass_header Server`), иначе VPL считает сервер устаревшим.

## Подводные камни

- VPL удаляет файлы исполнения перед запуском проверки. Чтобы `tb.v` дожил до неё, он должен
  быть в списке «Файлы, которые нужно оставить при запуске» (в `create_course.php` это сделано
  через `setfilekeeplist`). В интерфейсе: «Файлы исполнения» → «Файлы, которые остаются».
- Для запуска CLI Moodle 5 нужен `-d max_input_vars=5000`.
- Если копируете скрипты с Windows, окончания строк в `.sh` должны быть LF.

## Проверка

Через сам Moodle, на живом задании 1 и 5 (все четыре случая, оценки выставляются как ожидается):

| Решение | Оценка |
| --- | --- |
| верное | 100 |
| `y = ~a` вместо `y = a` | 0, в комментарии строки с ожидаемыми и полученными значениями |
| незаконченное `assign y = ;` | 0 и подсказка про «;» |
| мультиплексор с перепутанными входами | 50 (4 из 8) |

## CodeRunner: задания в виде теста (вариант без VPL)

Тот же курс, раздел 2: пять тестов «Задание N (CodeRunner)». Условие и окно с кодом на одной странице,
кнопка «Проверить» показывает таблицу «Что подали / Ожидалось / Получено». Когда все проверки зелёные,
ученик нажимает «Закончить попытку…», оценка записывается в журнал и открывается следующий тест (от 60 из 100).

Как устроено:

| Что | Где |
| --- | --- |
| Плагины | `qtype_coderunner` 5.10.9 и `qbehaviour_adaptive_adapted_for_coderunner` |
| Песочница | Docker-контейнер `jobe` (образ `yosis-jobe`, `jobe/Dockerfile`), только `127.0.0.1:4000`; язык `verilog` добавлен классом `jobe/VerilogTask.php` |
| Доступ Moodle | `https://cdod.sakoryagin.ru/jobe-<секрет>` через nginx (`/etc/nginx/fastpanel2-sites/fastuser/cdod.sakoryagin.ru.includes`) и API-ключ; секрет и ключ в `/root/vpl/jobe-path.txt` и `/root/vpl/jobe-key.txt`, в Moodle: `qtype_coderunner/jobe_host`, `jobe_apikey` |
| Вопросы | `coderunner/gen_questions.py` делает `questions.xml` из `tasks/`, `coderunner/create_quizzes.php` импортирует вопросы и создаёт тесты |

Moodle сам не пускает запросы на `127.0.0.1` и порты кроме 80/443 (настройки безопасности `curlsecurityblockedhosts`,
`curlsecurityallowedport`), поэтому Jobe открыт через nginx, а глобальные настройки не менялись.

Сборка и запуск песочницы:

```sh
docker build -t yosis-jobe jobe/
docker run -d --name jobe --restart unless-stopped --memory 1g --cpus 1 -p 127.0.0.1:4000:80 yosis-jobe
```

Базовый образ берётся из зеркала `cr.yandex/mirror/library/debian:12-slim`: прямые образы docker.io на сервере
отдают битые слои. Включение API-ключа (внутри контейнера, `app/Config/Jobe.php`) делается вручную и пропадёт, если
контейнер пересоздать.

Тест вопроса: тест подаёт входы фрагментом (`a = 1;`), шаблон оборачивает ответ ученика и фрагмент в тестбенч,
печатает выходы (`y=1`), сравнивается с ожидаемым выводом. Шаблон и тесты для каждого задания генерирует
`gen_questions.py`.
