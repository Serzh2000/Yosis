# Verilog в Moodle: автопроверка через VPL и Icarus Verilog

На `cdod.sakoryagin.ru` стоит плагин **VPL (Virtual Programming Lab) 5.0.1**. Код учеников
выполняет отдельный сервис `vpl-jail-system` (песочница) на том же сервере, Icarus Verilog 12
в песочнице доступен.

## Как устроено на сервере

| Что | Где |
| --- | --- |
| Плагин | `/var/www/fastuser/data/www/cdod.sakoryagin.ru/public/mod/vpl` |
| Песочница | сервис `vpl-jail-system` (`systemctl status vpl-jail-system`), конфиг `/etc/vpl/vpl-jail-system.conf`, журнал `/var/log/vpl/vpl-jail-system.log` |
| Адрес песочницы | только `127.0.0.1:8180` с секретным путём; секрет лежит в `/root/vpl/urlpath.txt` и записан в настройке Moodle `mod_vpl/jail_servers` |
| Лимиты | 120 с, 512 МБ, 100 процессов на запуск |
| Бэкап базы до установки | `/root/moodle-db-before-vpl-20261113.sql.gz` |

Песочница строит `/jail` из файлов сервера, поэтому после первого запуска несколько минут
идёт сканирование диска (порт 8180 открывается позже сервиса).

## Как сделать задание

1. В курсе: **Добавить элемент → Virtual programming lab**. Название и описание — любые.
2. **Файлы исполнения** (вкладка «Edit execution files»):
   - загрузите `vpl_evaluate.sh` (автооценка) и, по желанию, `vpl_run.sh` (кнопка «Запуск»);
   - добавьте тестбенч **`tb.v`** (см. `example/tb.v`).
3. **Execution options**: включите «Evaluate» (и «Run», если загрузили `vpl_run.sh`).
4. **Требуемые файлы** (Required files): имя файла ученика, например `half_adder.v`.
5. Ученик пишет код в редакторе VPL и жмёт «Оценить».

## Как писать тестбенч

Тестбенч печатает по строке на проверку, оценка = доля проверок PASS:

```
CHECK PASS a=1 b=0
CHECK FAIL a=1 b=1: ожидалось sum=0 carry=1, получено sum=1 carry=1
```

Модуль ученика подключайте под тем именем, которое вы указали в условии. Тестбенч должен
заканчиваться `$finish`, иначе симуляция остановится по таймауту 10 с.

Скрипт `vpl_evaluate.sh`: компилирует `tb.v` и все остальные `.v` (`iverilog -g2012`), запускает
`vvp`, считает строки `CHECK`. Ошибка компиляции, таймаут и запрещённые задачи
(`$system`, `$fopen`, `$readmem`, `$dumpfile` и т. п.) дают 0 с пояснением.

## Проверка

`example/` содержит тестбенч и два решения: `good.v` (100) и `bad.v` (75, ошибка в сумме).
Скрипт проверен на сервере для обоих и для файла с синтаксической ошибкой (0).
Проверку через сам Moodle сделайте в **Администрирование сайта → Плагины → Virtual programming
lab → Check jail servers**.
