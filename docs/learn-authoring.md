# Как писать уроки учебника

Учебник (`/learn`) состоит из двух книг: **«Verilog и плата»** (устройство описывают кодом) и
**«Схемы и плата»** (устройство собирают из блоков в графическом конструкторе). В обеих есть
уроки «на столе»: детали ставят на стол лаборатории и подключают к плате.

Урок — это **описание** (TypeScript-объект), а не страницы. Из описания код сам делает страницы,
задание и проверку. Все типы: `src/learn/content/authored/types.ts`. Образцы: `verilog-a.ts`
(`nand-gate`), `schematic-a.ts` (`nand-circuit`), `bench-verilog.ts` (`two-leds`).

## Где писать

Каждый автор пишет **только в своём файле** из `src/learn/content/authored/`:

| Файл | Тип | Главы (`chapter`) |
| --- | --- | --- |
| `verilog-a.ts` … `verilog-h.ts` | `VerilogLessonSpec[]` | `comb`, `arith`, `seq`, `counters`, `fsm`, `structure`, `board`, `projects` |
| `schematic-a.ts` … `schematic-j.ts` | `SchematicLessonSpec[]` | `gates`, `mux`, `arith`, `compare`, `flops`, `counters`, `shift`, `fsm`, `display`, `projects` |
| `bench-verilog.ts`, `bench-schematic.ts` | `BenchLessonSpec[]` | `board` (Verilog); `bench` (схемы) |

Файл экспортирует `export const specs: …[] = [ … ]`. Порядок уроков в файле — порядок в главе.
Чужие файлы, `index.ts`, `build.ts`, `types.ts` не править. Нужна правка общего — напиши об этом в
отчёте.

## Из чего состоит урок

- `id` — строчные латинские буквы, цифры и дефисы, **уникален во всей книге** (проверь по
  `grep -rn "id: 'твой-id'" src`). Не повторяй уроки, которые уже есть: список в
  `src/lib/learning-course.ts`, `src/lib/beginner-course.ts`, `src/lib/lessons.ts`.
- `chapter`, `title`, `minutes` (3–15).
- `theory` — 1–3 страницы объяснения: заголовок, текст (`md`), при желании листинг (`code`).
  В `md` можно: абзацы через пустую строку, списки `- `, **жирный**, `код`.
- `quiz` — вопрос с 2–4 вариантами; неверные варианты правдоподобны; `explain` объясняет, почему
  верный ответ верен. Квиз обязателен.
- `practice` — задание с проверкой (ниже), 2–3 подсказки: от намёка до почти ответа.

## Задание с проверкой (Verilog)

`starter` — полный файл с `module top (...)`, который **собирается, но не проходит проверки**
(обычно `assign y = 1'b0; // TODO`). `solution` — тот же файл, исправленный; **порты те же**.
`output` — имя выходного порта `top`, который читают проверки.

`cases` — проверочные случаи: `{ title, cycle, inputs, expected }`. Выход читается в конце такта
`cycle` (счёт с нуля); `expected` — двоичная строка той же ширины, что выход (`'1'`, `'0110'`). **Значения входов в `inputs` — строки, которые принимает симулятор: десятичное число (`'5'`), шестнадцатеричное (`'0x5'`) или двоичное **с приставкой `0b`** (`'0b0101'`). Строка без приставки — всегда десятичная: `'0101'` — это сто один и в 4 бита не поместится.** `expected` приставки не требует: это двоичная строка ширины выхода. Для многоразрядных входов удобно написать локальный помощник, который переводит двоичные строки в десятичные.
Для схем без такта берите `table(['a','b'], ['1','1','1','0'])` из `helpers.ts`: строки идут в
порядке таблицы истинности, первое имя — старший бит.

Для последовательных схем (есть такт) пишите `config`: `clock`, `reset`, `resetActiveLow`,
`resetCycles`, `periodNs`, `cycles`, `inputs` (начальные значения), `stimuli` (смена входов по
тактам: `{ cycle, inputs }`). Если `stimuli` нет, они берутся из `inputs` случаев. Образец —
урок `counter` в `src/lib/lessons.ts` (строка с `id: 'counter'`): такт `clk`, сброс `reset`,
паузы через `stimuli`. Сброс из `config.reset` держится только первые `resetCycles` тактов, посреди проверки симулятор его не подаёт: для «сброса посреди работы» заведите отдельный обычный вход (например `clear`). Входы `clk` и `reset` в `cases[].inputs` не пишите, если они заданы в
`config.clock` / `config.reset`: ими управляет симулятор.

Что должно быть верно (проверяют тесты):

1. Стартовая заготовка **проваливает** хотя бы один случай, но синтаксически верна.
2. Решение проходит **все** случаи через настоящий Yosys → Icarus.
3. Случаи различают разные неправильные решения: проверяйте и крайние, и «подлые» ситуации
   (сброс против разрешения, пауза, переполнение), а не только первый успешный шаг.

## Задание с проверкой (схема)

Ученик получает конструктор, в котором уже стоят порты: входы из `inputs` (слева) и выход
`practice.output` (справа). Он приносит блоки и провода. `solution` — эталон: `blocks` (`entry` — id
из библиотеки конструктора, `name`, `params` поверх умолчаний) и `wires` вида
`['a.Y', 'g.A']`. Контакты: у входа `Y`, у выхода `A`; у блоков — по описанию в
`shared/circuit-registry.ts` и `shared/circuit-blocks-*.ts` (`pins:`). Список блоков библиотеки:
`library` в `shared/circuit-registry.ts` (поле `id` у каждой записи `entry(...)`): `and`, `or`,
`xor`, `nand`, `not`, `mux`, … Блок такта — вход с именем `clk`. Внутренние тактовые
(`clock27`, делители) в обучении не используйте: ученику нужны только внешние входы.

Для схем без такта тест сначала проверяет эталон быстрым вычислителем, потом через симулятор.
Для схем с тактом укажите `config.clock` (`'clk'`) и сопровождающие поля как в Verilog.

Пустая заготовка ученика не соберётся (выход не соединён): это нормально.

## Задание на столе

`BenchLessonSpec`: что лежит на полке (`parts`: `{ part, count }`, id деталей из
`src/lib/lab/catalog.ts`, например `led`, `button`, `sw-toggle`, `buzzer`, `seg1`, `dip`) и
шаги-проверки (`steps`): `placed` — на столе не меньше `count` деталей, `wired` — не меньше
`count` деталей подключены к плате, `pins` — всего подключено не меньше `count` выводов.
Каждая деталь шага должна быть на полке. Ошибки в `id` деталей ловит тест.

## Каким должен быть текст

Читатель — школьник или взрослый новичок, говорящий по-русски; он ничего не знает про ПЛИС.

- Каждое новое слово объясняй там, где оно впервые появилось. Не пиши «очевидно», «просто».
- Один урок — одна идея. Короткие абзацы, конкретные примеры из жизни платы (кнопка, светодиод).
- Таблицы истинности, диаграммы времени и листинги кладите в `code` отдельным блоком.
- Тон дружелюбный, на «ты», как в существующих уроках. Без капслока и восклицаний через строку.
- Обещай только то, что проверяют случаи. Не придумывай поведение платы: на плате светодиод
  включается нулём (`led_n`), кнопка при нажатии даёт 1 — как в курсе (`beginner-course.ts`).
- Факты должны быть верными. Сомневаешься — проверь запуском.

## Проверка работы

Проверять только свой файл (`LEARN_FILE` — имя файла без `.ts`):

```bash
LEARN_FILE=verilog-b npx tsx --test tests/learn-authored.test.ts
LEARN_FILE=verilog-b npx tsx --test tests/learn-authored.integration.test.ts
npx prettier --write src/learn/content/authored/verilog-b.ts
```

Первая команда быстрая (структура, быстрые проверки схем), вторая гоняет решения через
симулятор (около секунды на урок). Оба теста должны пройти. Если падает тест не из-за вашего
файла (чужой файл не собирается), подождите и повторите: файлы пишутся параллельно.
Типы всего проекта проверяет `npx tsc --noEmit -p tsconfig.client.json`: ошибки в чужих файлах
не ваши.
