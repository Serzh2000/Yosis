# Yosis · FPGA Studio

Учебная IDE для Sipeed Tang Nano 20K. Рабочие вкладки ведут от Verilog к схемам, временным диаграммам, виртуальной плате и физической сборке. Есть светлая и тёмная темы, проекты и задания для начинающих.

Сборка и симуляция выполняются сервисом на Linux-сервере или локально. Для сервера подготовлены Docker, HTTPS-прокси, персональные ключи доступа, изоляция заданий и сохранение проектов. [Развёртывание](deploy/README.md). USB-плата подключается к браузеру ученика; аппаратная приёмка установки DirtyJTAG ещё не завершена.

## Запуск

Нужен Node.js 22.13 или новее. Yosys устанавливается вместе с зависимостями и работает в отдельном процессе через WebAssembly.

```powershell
npm install
npm run dev
```

Откройте адрес, напечатанный Vite, обычно <http://127.0.0.1:5173>. Сервис сборки слушает только `127.0.0.1:3001`.

Если запуск npm в Windows нарушен из-за PATH, используйте включённый скрипт:

```powershell
./scripts/npm.ps1 install
./scripts/npm.ps1 run dev
```

Для запуска собранного интерфейса:

```powershell
npm run build
npm start
```

## Работа с проектом

Кнопка «Создать проект» в шапке открывает полноэкранное окно: с нуля на Verilog, из логических элементов, на основе примера или импорт JSON. Затем задайте название и верхний модуль, проверьте файлы и физические выводы. В том же окне находятся «Мои проекты» и действия текущего проекта. Название в шапке показывает открытый проект.

Общее дерево файлов доступно в рабочих вкладках через кнопку «Файлы». Нажатие на `.v`, `.sv` или файл заголовка открывает «Код», на `.ysch` — «Конструктор», на `.cst` — «Выводы». Добавление, переименование и удаление находятся в этом дереве; удалённый файл можно восстановить. Иерархия модулей появляется ниже файлов на вкладках RTL и Gowin. На узком экране дерево открывается поверх рабочей области.

«Конструктор» содержит 18 типов элементов, шины 1–64 бит, соединения, свойства и undo/redo. Соедините выходной контакт с входным. Несовместимые ширины, незаполненные входы, несколько источников и комбинационные петли блокируют сборку. Исходник `.ysch` сохраняется; Verilog создаётся для запуска настоящих Yosys, Icarus и nextpnr. Его можно посмотреть в конструкторе. [Концепт и ограничения](docs/schematic-authoring-plan.md).

В «Выводах» выберите порт или бит шины, контакт QN88 и нажмите «Назначить». Команды IO_LOC/IO_PORT сохраняются в `.cst`, комментарии и остальные свойства остаются в файле. Карта поддерживает масштаб, перемещение и фильтр банков. Это Pin Planner; для сложных стандартов ввода-вывода доступен текстовый CST.

«Синхронизация» сохраняет проекты и учебный прогресс на сервере. Сервер выполняет сборку независимо от сохранённой копии проекта; USB остаётся у браузера ученика.

В инспекторе нажмите на имя примитива, например `$pmux`, чтобы открыть карточку с обозначением, объяснением и примером. Названия параметров и плитки ресурсов тоже открывают справку. Числа ширины отображаются в битах, флаги знаковости — словами, полярность такта — фронтом или спадом. Исходная запись Yosys остаётся доступна в карточке.

## Встроенные примеры

В окне «Создать проект» выберите «На основе примера»: каталог содержит 108 проектов, четыре уровня сложности и двенадцать тем. Каждый проект содержит Verilog с учебными комментариями и `board.cst` для Tang Nano 20K. Открытие создаёт отдельную копию; свои правки можно продолжить через библиотеку проектов.

Среди схем — сумматоры, знаковая арифметика, CRC и Хэмминг, антидребезг, таймеры, FIFO, RAM/ROM, UART, SPI/I²C, автоматы, FIR, DDS и учебный процессор. [Полный список](docs/example-library.md) содержит цели и темы каждого опыта. Ниже — начальные схемы для знакомства.

| Пример | Что изучаем |
| --- | --- |
| Логическое выражение | AND + OR, таблица истинности и LUT |
| Кнопка → LED | Непрерывная связь `assign`, активный уровень 0 |
| Инвертор NOT | Инверсия логического уровня |
| AND · OR · XOR | Три операции над двумя входами |
| Мультиплексор | Выбор данных управляющим сигналом |
| Счётчик | Шесть регистров, синхронный сброс и пауза |
| Мигалка 27 МГц | Делитель частоты и расчёт периода |
| Бегущий огонь | Кольцевой сдвиг одного бита |
| Яркость через PWM | Частота и доля включённого состояния |
| Автомат светофора | Состояния, время пребывания и переходы |
| Иерархическая ALU | Регистры, выбор операции и вложенный сумматор |
| NAND · NOR · XNOR | Инверсия основных логических операций |
| Полусумматор | Сумма двух битов и перенос |
| Компаратор | Меньше, равно, больше |
| Декодер 2 → 4 | Двоичный адрес и one-hot выход |
| Приоритет кнопок | Выбор запроса и сигнал valid |
| Бит чётности | Редукция XOR и контроль чётности |
| Сдвиговый регистр | Последовательные данные, синхронизация кнопки |
| Регистр с загрузкой | Снимок числа и удержание |
| Счётчик вверх / вниз | Выбор направления и переполнение |
| Счётчик с насыщением | Удержание на предельном значении |
| Счётчик кода Грея | Один меняющийся бит между соседними значениями |
| Счётчик Джонсона | Инвертированная обратная связь, цикл из 12 состояний |
| Одно нажатие → переключение | Синхронизатор и детектор фронта, без фильтра дребезга |

Комментарии объясняют поведение кода, полярность кнопок и LED, тактирование и назначение каждого физического вывода. Для короткой симуляции мигалки и бегущего огня поставьте параметр делителя `4`, для светофора — `SECOND_TICKS = 4` и 40 циклов, для PWM — `PWM_BITS = 3`. Перед аппаратной сборкой верните исходные параметры для генератора 27 МГц. Замедленное воспроизведение виртуальной платы меняет скорость просмотра, сохраняя число тактов в схеме.

Во вкладке «Код» измените Verilog и запустите синтез. «RTL» показывает схемные элементы, «Gowin» — реальные примитивы и таблицы LUT из параметра `INIT`. Иерархия и инспектор находятся на этих вкладках отдельно от редактора. Нажатие на ссылку исходника возвращает к нужной строке кода.

Проекты сохраняются отдельными записями IndexedDB с постоянными ID. Библиотека поддерживает переименование, дублирование и удаление. Старые проекты из localStorage переносятся автоматически. Экспорт и импорт используют JSON. Результаты сборок хранят снимок исходников и журнал; ротация ограничивает их возраст, число и объём. После правки результат помечается устаревшим до следующей успешной сборки.

## Что означают результаты

- RTL показывает схему после преобразования процедур Yosys и оптимизации, до отображения на Gowin. Логические операции рисуются схемными символами, мультиплексоры — с входом выбора, регистры — с обозначением тактового входа, сложение — блоком «+». Многобитная операция остаётся одним символом с подписанной разрядностью. Вложенные модули и операции без специального символа показываются подписанными блоками.
- Технологический вид получен командой `synth_gowin -family gw2a -noflatten -noiopads`: выбранное семейство соответствует Tang Nano 20K, иерархия сохраняется для навигации. Затем `iopadmap` добавляет буферы выводов только в верхний модуль; внутренние модули сохраняют обычные сигнальные порты.
- Счётчики показывают примитивы после синтеза. Итоговая загрузка FPGA определяется упаковкой и размещением в nextpnr.
- Ссылки на исходники доступны только там, где Yosys сохранил атрибуты происхождения. Одна строка может соответствовать нескольким элементам. Источники в библиотеке Yosys обозначены отдельно и не открываются как файлы проекта.

Визуальное создание устройства из блоков и соединений описано в [плане конструктора схем](docs/schematic-authoring-plan.md). Это будущий способ ввода, который будет создавать Verilog и использовать существующие `.cst`, симуляцию и сборку.

## Симуляция и временные диаграммы

Встроенные комбинационные примеры открываются с готовым сценарием полного перебора входов. В Logic Lab это восемь сочетаний `000…111`. Начальные нули в полях — первая строка сценария; остальные уровни заданы в «Последовательности входов». Кнопка «Постоянные входы» отключает изменения. «Перебрать входы» создаёт новую последовательность для суммарно 1–8 входных битов; у схем с тактом и сбросом оставляет начальные периоды для сброса. Настройки и собственные шаги сохраняются при переименовании и повторном синтезе. Виртуальная плата использует отдельные ручные переключатели.

Для просмотра готовых VCD дополнительные инструменты не нужны. Для запуска симуляции нужен Icarus Verilog (`iverilog` и `vvp`). Сервис ищет их в PATH или в локальной папке `.tools/iverilog/mingw64/`.

На Windows x64 можно подготовить локальный симулятор:

```powershell
npm run setup:iverilog
```

Установщик загружает закреплённые версии из официального репозитория MSYS2, проверяет SHA256 и распаковывает их в `.tools/`. Системные настройки и PATH не меняются. На Linux/macOS установите Icarus через пакетный менеджер.

1. Выберите пример «Счётчик» и синтезируйте его.
2. Откройте отдельную вкладку «Диаграммы».
3. Укажите `clk`, сброс `reset_n` с активным уровнем 0, период 10 нс, два цикла сброса и `enable = 1`.
4. Нажмите «Симулировать». Используйте курсор, масштаб и выбор сигналов; для шин доступны двоичный, десятичный и шестнадцатеричный форматы.

Раздел «Последовательность входов» задаёт изменения уровней в начале выбранных периодов. Нумерация начинается с 0. Изменения выполняются через 1 пс после границы периода, чтобы не совпасть с отрицательным фронтом такта. Начальные значения используются до первого изменения.

Сервис моделирует синтезируемый RTL, экспортированный Yosys, и автоматически создаёт testbench. Симуляция функциональная, без задержек распространения. Произвольные testbench пока не редактируются в IDE; их цифровые VCD можно импортировать. Снимок проекта, testbench, VCD и журнал сохраняются в `.simulations/`.

## Виртуальная плата и задания

Во вкладке «Виртуальная плата» загрузите текущий Verilog. Шесть LED показывают выбранный выходной порт: можно выбрать биты и активный уровень. Воспроизведение, шаг по такту и курсор читают реальные значения VCD; неизвестные X/Z показаны явно. Переключатели меняют входы на выбранном периоде и запускают новый прогон со всей накопленной последовательностью. Это модель логики вашей схемы, без электрических свойств и задержек реального чипа.

Во вкладке «Задания» доступны НЕ, И, мультиплексор и счётчик. У каждого задания есть вопрос о поведении, заготовка проекта, подсказка и проверка решения настоящим Icarus. Проверки сравнивают выходные сигналы с ожидаемыми значениями для указанных воздействий.

## Выводы и карта кристалла

`.cst` связывает порты Verilog с физическими выводами FPGA (`IO_LOC`) и задаёт электрические свойства (`IO_PORT`). Во вкладке «Выводы .cst» находятся редактор и список назначений. Логический синтез игнорирует эти файлы; nextpnr использует выбранный `.cst`.

Шаблоны и все встроенные примеры используют [распиновку Apicula](https://github.com/YosysHQ/apicula/blob/master/examples/tangnano20k.cst). Счётчик имеет 6 бит для шести LED; ранее сохранённые восьмибитные проекты остаются в библиотеке. В логическом примере вход `c` назначен на UART_RX (вывод 70), это внешний сигнал от USB-UART. Имена портов в `.cst` должны совпадать с вашим модулем.

Для физической сборки подготовьте локальные nextpnr и Apicula (на проверенной Windows-конфигурации нужен Python 3.13 x64):

```powershell
npm run setup:gowin
```

Установщик создаёт изолированную среду `.tools/gowin`, устанавливает закреплённые версии из PyPI и проверяет зависимости. Затем перезапустите сервер IDE.

Во вкладке «Кристалл» выберите `.cst`, целевую частоту и запустите размещение. Сервис проверяет соответствие исходников результату синтеза, создаёт отдельный плоский нетлист, запускает nextpnr для `GW2A-18C`, затем генерирует `design.fs` через Apicula. Доступны отчёт о времени и выгрузка артефактов.

Карта строится по настоящим BEL и ROUTING из nextpnr: плотность размещённых ячеек, количество использованных PIP, категории элементов и происхождение по иерархии. Нажмите на тайл, чтобы изучить его элементы. Можно импортировать `placement.json`. Интенсивность показывает число элементов или PIP, а не температуру, энергопотребление или процент ёмкости тайла. Результаты хранятся в `.physical/`.

## Настоящая плата

«Подключение» открывает UART-терминал через Web Serial: выбор порта, скорость, приём и отправка строк. Требуется браузер с поддержкой Web Serial. Работа на физическом устройстве в этой среде ещё не проверена.

Добавлен экспериментальный прямой WebUSB/MPSSE/JTAG: выбор платы, проверка ID/Status/UserCode, текущая сборка или свой `.fs`, CRC, прогресс и SRAM-загрузка. Скачивание помощника отсутствует. Реальная браузерная запись ещё требует подтверждения; штатный FTDI-драйвер Windows может блокировать WebUSB. [Подробности и ограничения](docs/browser-programming.md).

На подключённой Tang Nano 20K ранее успешно загружен свежий битстрим Yosis: пользователь подтвердил чередование двух групп по три LED. Та проверка выполнялась установленным Gowin Programmer только в SRAM; исходная flash сохранена. [Работающий проект](hardware/clocked-pattern/README.md), [история диагностики](hardware/README.md). Расширенная симуляция, маршруты отдельных сигналов и RISC-V остаются следующими этапами [плана](docs/implementation-plan.md).

## Проверки

```powershell
npm test
npm run build
npm run smoke
npm run smoke:simulation
npm run smoke:learning
npm run smoke:physical
npm run smoke:templates
npm run smoke:examples
npm run smoke:example-behavior
npm run smoke:new-example-behavior
npm run smoke:wizard
npm run audit:rtl
```

Основной smoke проверяет настоящий синтез примеров, ошибки и артефакты. Проверка симуляции запускает собственный API на порту 3100. Проверка заданий использует уже работающий API на 3001. Физическая проверка, проверка шаблонов и проверка всей библиотеки запускают менеджеры напрямую; им нужны подготовленные локальные инструменты. `smoke:examples` проверяет каждый бит `.cst`, синтез, Icarus, размещение, карту 56 × 55 и битстрим; отчёт записывается в `.physical/example-smoke-report.json`. Для одного проекта можно выполнить `npm run smoke:examples -- --only=traffic`.

`smoke:example-behavior` проверяет через работающий API 3001 короткие варианты мигалки, бегущего огня, PWM и светофора: точное число фронтов между переключениями, кольцевой сдвиг, изменение заполнения 25% → 75% и полный цикл состояний.

`smoke:new-example-behavior` проверяет 13 дополнительных схем: все комбинации логики, задержки синхронизации, загрузку и удержание, насыщение, полные циклы Грея и Джонсона, два отдельных нажатия кнопки. Результаты находятся в `.simulations/new-example-behavior-report.json`.

`audit:rtl` проверяет сохранённые настоящие RTL-нетлисты всех примеров после `smoke:examples`: ширины портов, драйверы, параметры регистров, соединения и сохранение иерархии. Отчёт: `.builds/rtl-example-audit.json`.
`npm run audit:rtl -- --probes` дополнительно выводит реальные примитивы Yosys из отдельной схемы со знаковой арифметикой, one-hot мультиплексором, защёлкой, разными фронтами и сбросами.

`smoke:wizard` использует API 3001 для проектов, созданных мастером: своя заготовка и иерархическая ALU с новым именем верхнего модуля проходят синтез, симуляцию, размещение и упаковку битстрима. Адрес можно изменить переменной `YOSIS_API`.

## Структура

| Папка | Назначение |
| --- | --- |
| `src/` | Редактор, дерево модулей, SVG-схемы, инспектор LUT |
