# Logra · FPGA Studio

[English](README.md) · **Русский**

Учебная среда для платы **Sipeed Tang Nano 20K**, которая открывается в браузере. Она ведёт
начинающего по всему пути: написать Verilog, увидеть схему, проверить её на временной диаграмме,
собрать на виртуальном столе с деталями и загрузить в настоящую плату.

Устанавливать вендорскую IDE не нужно: синтез, размещение и симуляцию выполняют открытые
инструменты — Yosys, nextpnr, Project Apicula и Icarus Verilog.

![Logra: редактор кода](docs/images/code.png)

## Два языка, телефон и компьютер

- **Русский и английский.** Переключатель (`RU` / `EN`) стоит в шапке; пока выбор не сохранён,
  язык берётся из браузера. Переведены весь интерфейс, оба курса, все 275 примеров и сообщения
  сервера. Исходный код, файлы `.cst` и комментарии внутри файлов проекта остаются как написаны.
  Как это устроено: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- **Мобильная версия.** Уже 768 px: левое меню становится нижней панелью вкладок, библиотека и
  свойства конструктора — нижними шторками, на холсте работает щипок-масштаб, цели касания не
  меньше 44 px. Десктоп не менялся. Подробности и снимки: [docs/mobile/README.md](docs/mobile/README.md).
- **Графитовая тема**, тёмная и светлая.

## Конструктор

Схему можно нарисовать, а не печатать Verilog. В библиотеке около сотни блоков: вентили, шины,
арифметика, триггеры и регистры, счётчики, дешифраторы и шифраторы, память, кнопки платы,
светодиоды и такт 27 МГц. У каждого блока есть карточка с символом, пояснением и временной
диаграммой или таблицей истинности. Символы рисуются в двух системах обозначений, **ANSI** и
**ЕСКД** (переключатель над холстом). Вкладка **Verilog** (и вкладка **Код** у схемного проекта)
показывает получившийся код: схему и её Verilog можно сравнивать построчно.

Новый схемный проект начинается с пустого поля. Готовые схемы (кнопка → светодиод, вентили,
мигалка, счётчик на светодиодах, бегущий огонь) открываются одним щелчком из окна **«Примеры»**;
кнопкам и светодиодам вывод платы назначается сам.

## Лаборатория

Плата лежит на виртуальном столе. Вокруг неё ставятся детали, провода тянутся от вывода детали
к контакту гребёнки, а схема проекта исполняется в браузере непрерывно — как на настоящей плате,
только медленнее.

- **85 деталей**: светодиоды и индикаторы, кнопки и клавиатуры, датчики, моторы и сервопривод,
  сдвиговые регистры, OLED и ЖК-экраны, часы, память и датчики на шине I²C, лента WS2812B,
  АЦП, дальномер, ИК-пульт, клавиатура PS/2.
- **Приборы**: логический анализатор, пробник, частотомер, вольтметр, генератор импульсов,
  UART-терминал.
- **Настоящие протоколы**: модели деталей отвечают на I²C, SPI, 1-Wire и UART побитно, поэтому
  схема, которая работает на столе, написана так же, как для железа.
- **Питание по желанию**: можно включить режим, в котором у каждой детали есть выводы VCC и GND
  и её нужно запитать от контактов платы.

Что на каком контакте, лаборатория берёт из файла `.cst` проекта, поэтому стол и планировщик
выводов всегда согласованы.

## Примеры

В библиотеке **275 готовых проектов** с комментариями в коде, назначением выводов и уроком:
цель, что наблюдать и что попробовать изменить.

- 108 схем от первой логической функции до учебного процессора: сумматоры, счётчики, автоматы,

## Быстрый старт

Нужен [Node.js](https://nodejs.org/) 22.13 или новее.

```sh
npm install
npm run dev
```

Откройте <http://127.0.0.1:5173>. Синтез и схемы работают сразу: Yosys ставится вместе с
зависимостями и запускается как WebAssembly. Приложение открывается на окне «Создать проект».

Для остальных вкладок нужны ещё два инструмента:

| Что               | Для чего              | Как поставить                                                             |
| ----------------- | --------------------- | ------------------------------------------------------------------------- |
| Icarus Verilog    | «Диаграммы», курс     | Linux: `sudo apt install iverilog` · Windows: `npm run setup:iverilog`    |
| nextpnr и Apicula | «Кристалл» и битстрим | `npm run setup:gowin` (нужен Python 3 с `venv`; проверено на Python 3.13) |

Оба установщика кладут инструменты в папку `.tools/` проекта и ничего не меняют в системе.
Версии инструментов: Yosys 0.70 (YoWASP), nextpnr-himbaechel-gowin 0.11, Apicula 0.35.

## Запуск на сервере

На сервере приложение работает под [PM2](https://pm2.keymetrics.io/) на одном порту:

```sh
pm2 start ecosystem.config.cjs
```

Первый запуск сам ставит зависимости и собирает интерфейс. Приложение открывается на
`http://<адрес-сервера>:4444`.

- В этом режиме вход не требуется; проекты каждого браузера хранятся отдельно.
- Загрузка в плату из браузера работает только по HTTPS или с `localhost` — так устроен WebUSB.
  Поставьте перед приложением обратный прокси с сертификатом.
- Вход по персональным ключам включают переменные `YOSIS_PUBLIC_ORIGIN` (HTTPS-адрес сайта) и
  `YOSIS_USERS_JSON` (имя → ключ от 32 символов).
- Число одновременных сборок задают `YOSIS_BUILD_CONCURRENCY`, `YOSIS_SIMULATION_CONCURRENCY`
  и `YOSIS_PHYSICAL_CONCURRENCY` (от 1 до 8). Проверка кода (`/api/syntax`) и подготовка схемы
  для лаборатории (`/api/lab`) идут через прогретые воркеры Yosys, которые служат много заданий
  подряд; их число задают `YOSIS_SYNTAX_CONCURRENCY` и `YOSIS_LAB_CONCURRENCY` (по умолчанию
  треть ядер, не больше 4). Одинаковые исходники проверяются и готовятся один раз.

(Имена переменных `YOSIS_*` и ключей хранилища браузера `yosis.*` намеренно сохраняют прежнее
рабочее имя проекта: так продолжают работать уже развёрнутые серверы и сохранённые проекты
учеников.)

## Настоящая плата

Вкладка «Подключение» загружает битстрим в SRAM кристалла через WebUSB — без программатора
производителя. На Windows штатная прошивка отладчика платы недоступна браузеру, поэтому в той
же вкладке есть установка прошивки DirtyJTAG в отладчик BL616 с резервной копией исходной.

Проверено на настоящей плате: чтение флеш-памяти отладчика, установка прошивки, привязка
драйвера WinUSB и загрузка битстрима в SRAM через DirtyJTAG из браузера.

Не сверено с платой: расположение контактов питания на гребёнках в лаборатории — оно взято
с карточки распиновки, и действие исправления цепочки переноса из
[docs/rtl-gowin-quality.md](docs/rtl-gowin-quality.md).

## Как это устроено

```
src/        интерфейс: React 19, TypeScript, Vite
  lib/lab/  лаборатория: симулятор вентильной схемы, модели деталей; 3D-стол (three.js) в components/lab/reference
  i18n/     английские словари (файл на область); грузятся только для английского интерфейса
server/     API на Express: очереди синтеза, симуляции и размещения, каждое задание в своём процессе
shared/     форматы проекта и результатов, общие для браузера и сервера; ядро перевода
tests/      юнит-тесты (node:test)
e2e/        сквозные тесты в браузере (Playwright), в том числе раскладка для телефона
hardware/   исходники прошивки отладчика DirtyJTAG для BL616
textbook/   учебное пособие по цифровой схемотехнике и ПЛИС: LaTeX, примеры на Verilog, PDF
```

Подробнее — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): слои, правила импортов, протокол
заданий, переменные окружения. Качество генерации RTL и отображения на Gowin с открытыми
замечаниями к инструментам — в [docs/rtl-gowin-quality.md](docs/rtl-gowin-quality.md).

Схема проекта проходит три разных пути:

1. **Синтез** — Yosys строит схему RTL и отображает её на примитивы Gowin.
2. **Размещение** — nextpnr раскладывает примитивы по кристаллу GW2AR-18, Apicula собирает
   битстрим.
3. **Лаборатория** — Yosys сводит схему к вентилям и триггерам, а браузер исполняет их сам,
   миллионы тактов в секунду.

## Проверки

```sh
npm run check        # типы
npm run lint
npm run format:check
npm run test:unit    # быстрые тесты без внешних инструментов, секунды
npm run test:integration # с настоящими Yosys, Icarus и Express, несколько минут
npm test             # оба набора
npm run test:e2e     # сценарии в браузере: компьютер и телефон
npm run check:bundle # стартовый JavaScript должен быть меньше 600 КиБ
```

Тесты запускают настоящие инструменты: каждый пример лаборатории синтезируется и работает
в симуляторе со своим столом. Те же проверки идут при каждом пуше в GitHub Actions
([`.github/workflows/ci.yml`](.github/workflows/ci.yml)).

Чтобы обновить снимки экрана в README при запущенном приложении (`npm run dev`):
`npx tsx scripts/capture-screenshots.mts`.
